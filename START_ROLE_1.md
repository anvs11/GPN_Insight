## Срез для передачи команде на 2026-11-06

Реализован текстовый путь участника 1: строгий JSON manifest → read-only preview → повторная полная проверка и commit через существующий Repository → маскирование → TextNormalizer → интеграция с настоящим AnalysisService участника 2. Схемы, регистрацию SQLite и orchestration/checkpoints предоставляет участник 3; они переиспользованы, не реализованы заново участником 1.

Результаты текущего среза:

- importer проверяет UTF-8, размер/глубину JSON, повторные ключи/неизвестные поля, dataset/product/даты/ID; медиа отклоняет целиком. Preview не пишет, ошибки чтения БД не выдаёт за пустую базу.
- Текстовый commit использует import_commit/register_dataset, серверный UUID и ImportResult counts. Повтор не создаёт версий/дублей, обновление сохраняет идентификаторы, решения и историю; ошибка до commit откатывается, потеря ответа после commit не отменяет импорт.
- masking.py и TextNormalizer сохраняют исходник и переданный pipeline контекст; маскируют телефоны/email/карты с Luhn/помеченный ИНН/20-значные счета. Имена/адреса не гарантированы, госномера сохраняются. Normalizer не пишет в БД; окончательные fragment ID и атомарную запись/checkpoint выполняет pipeline.
- Общий сервис доступен через POST /api/v1/imports?dry_run=true, POST /api/v1/imports, GET /api/v1/imports и CLI import --manifest ... [--dry-run]. Multipart ограничен до разбора и по частям/заголовкам, files запрещены в этом срезе; ошибки русские, без исходного текста. Единственная новая закреплённая зависимость — python-multipart==0.0.33, согласованная с участником 3.
- build_text_profile/build_text_pipeline связывают Normalizer и AnalysisService с проверками точных цитат/источников/metadata/профиля/режима. Обычный сервер умеет подключать совпадающий явный профиль через APP_PROCESSING_PROFILE_PATH и настоящую фабрику text_gateway. Без реальной конфигурации сохраняется 503 INTEGRATION_NOT_READY; live-адаптер отсутствует, fixture gateway в обычный сервер не подставлен.
- Подготовлены четыре синтетических обращения, контрактные примеры нормализации/импорта и инструкции IMPORT_HTTP, TEXT_INTEGRATION, RUNTIME_PROFILE. Существующая authored seed-demo не превращалась в imported. docs/EFFECT.md содержит методику; реальные исходные показатели/экономия пока не измерены.

Приёмка: 459 backend-тестов прошли, одно прежнее предупреждение; реальный localhost HTTP/CLI и ordinary app.main:app проверены на отдельных SQLite/recordings. Получены inserted=4 → unchanged=4 → updated=1/unchanged=3, 409 RUN_ACTIVE/IMPORT_ACTIVE, 413/422, rollback, 12 reused checkpoints после повторного запуска/рестарта и сохранность решений/истории. Unknown replay/material/provenance ошибки остаются явными. Проверки synthetic/authored не являются оценкой живой Qwen; Windows/live/browser в текущем срезе не проверены.
