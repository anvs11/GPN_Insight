# Синтетический набор проверки медиаимпорта

Четыре искусственных обращения с WAV, MP3, PNG и JPEG. Это не данные компании, не независимый benchmark и не результат моделей. Текстовые просьбы придуманы; аудио содержит только тишину, изображения — одноцветные поля. Содержимое вложений не доказывает текстовые потребности и не используется для измерения распознавания.

Набор воспроизводится helper-функцией `scripts.media_import_fixture.write_fixture` из `backend/`. WAV: mono PCM16, 8000 Hz, 0,1 с, сгенерирован стандартным wave. MP3: десять синтетических MPEG-1 Layer III кадров 128 kbps/44100 Hz с пустыми granules, без речи/ID3; проверяется разбор mutagen, качество декодирования/ASR не измерялось. PNG/JPEG: RGB 16×16, цвет (10,80,140), созданы Pillow 13.0.0. Внешние записи/изображения и runtime encoder не использовались.

Применять к отдельным APP_DB_PATH, APP_UPLOAD_ROOT, APP_TMP_ROOT. Удобная безопасная приёмка из backend:

```sh
../.venv/bin/python -X utf8 -m scripts.check_media_import
```

Скрипт сам создаёт новую SQLite и собственный localhost-сервер, проверяет preview/commit/repeat/delta/restart/CLI. Для ручного CLI используйте существующий `app.cli import --manifest ../data/media-import/manifest.json [--dry-run]` после подготовки отдельной SQLite. Не запускайте media CLI параллельно серверу над той же БД/корнями: общий guard действует внутри одного процесса.

Существующий `data/demo/manifest.json` не заменён. Медиаимпорт не подключает ASR/VL, медийный replay или binary API источников. Отдельные аварийные проверки с настоящими остановками процессов находятся в `tests/test_import_recovery.py`.
