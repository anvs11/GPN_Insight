# Мониторинг и отчёты — новый интерфейс

10.11.2026, `feat/monitoring-workspace` от 91a4b78. Всё находится в прежнем репозитории. Новых зависимостей, CDN, клона или внешних модельных вызовов нет.

## Что доступно

Карточка обращения разделена линиями и крупными заголовками. Под сведениями об источнике кнопка раскрывает/скрывает исходный текст и подготовленные расшифровки/описания изображений. Покрытие — отдельные счётчики материалов; потребность/категория/приоритет/основание/неизвестности/цитаты собраны в одном блоке без повторного списка. ID цитаты вынесен в подпись, модельный ID — в технические сведения. «Подготовленные фрагменты» по умолчанию свёрнуты и объясняют привязку цитат и ограничения маскирования. Реальные ошибки обработки остаются видимыми. Правила restricted/synthetic не ослаблены. 352 frontend tests/build/lint и HTTP5/restart прошли: `var/frontend-media-http-4483309492864daaa7345b5990974a89/result.json`. Внешний вид пока требует браузерной приёмки пользователем.

Мелкие правки 10.11: из блока «Вебнефть» убран неработающий указатель выбора, приоритеты на обложке увеличены до 15px. Кнопка темы в верхней панели переключает светлую/тёмную палитру, включая формы и модальные окна. Выбор сохраняется в localStorage этой установки браузера; при недоступном хранилище переключение работает в текущей сессии. Печать и PDF остаются на белых страницах. Обоснование категории/приоритета находится в источнике → «Покрытие и оценки»: явная подпись, reason, цитаты, неизвестности и provenance. Authored обоснование в демо не выдаётся за результат живой модели.

Основные страницы — «Мониторинг» и «Отчёты». Мониторинг разделяет **темы** и **исходные обращения**; последние берутся из реестра целиком, включая ещё не обработанные и не назначенные теме. Карточки содержат категорию/приоритет, исходную дату, статус и происхождение, число обращений/вложений. Даты темы означают первое обращение, не выдуманную дату создания продуктовой задачи. Поиск, категории, приоритеты, статус, даты Москвы и повторяемость применяются кнопкой. Пагинация — 24 карточки.

Вся карточка открывает окно по центру с размытым фоном, доказательствами, источниками/медиа, оценками и историей. Галочка и «+ В отчёт» выбирают объект отдельно. Окно поддерживает Escape/возврат фокуса и закрытие по фону; при сохранении решения закрытие блокируется. Оценки и редактор описания можно свернуть без потери черновика. Техническая версия паспорта спрятана в пояснении: это редакция сценария и границ темы.

Загрузка содержит только текст и медиа. Обработка — отдельный раздел: читает уже сохранённые обращения и строит потребности/темы; replay требует известных записей. Медиа проходят выбор JSON+файлов → предпросмотр → подтверждение → отдельную обработку. «? Правила работы» доступны по наведению, фокусу и нажатию; реальные ошибки и неизвестные квитанции остаются видны. Необязательное «Уточнить связи» находится в дополнительных действиях. Неуверенная классификация попадает в «Неразобранное» и аналитику без обязательной эскалации человеку. Уточнение темы — добровольное исправление аналитика. Формы остаются смонтированными при скрытии. Для решения темы доступны new/needs_research/linked/deferred/declined/implemented с обязательными полями и проверкой версии/истории повторным GET. Это не закрытие исходного тикета и не автоматическое создание задачи.

Карта справа показывает до четырёх тем текущей страницы и до шести источников. Каждое ребро означает сохранённую связь source→topic; положение узлов не интерпретируется как сходство или риск. На узел темы можно нажать. На узком экране карта скрывается, все основные действия доступны списком. Никакого числового скора или новой классификации не добавлено; `potentially_critical` остаётся потенциальным сигналом с обоснованием в источнике. `unknown` и отсутствие актуальной оценки различаются.

## Подборка и архив

Галочкой «В отчёт» выбираются до 30 тем/обращений. На странице отчётов задаются название, резюме и комментарий автора. Они **не меняют бизнес-решений**. Выбор и черновик переживают переход между страницами, но не перезагрузку вкладки. Подборка сохраняется только по явной кнопке на сервере. Один источник, выбранный отдельно и через тему, не удваивает `distinct_source_count`; число выбранных объектов показывается отдельно.

Выбор содержит `kind/id/version/revision`. SHA-256 revision учитывает содержимое обложки и текущие результаты анализа: partial→complete может изменить результат при прежней source_version. Старый выбор получает `409 REPORT_SELECTION_STALE`. Кнопка «Обновить версии» перечитывает карточки, сохраняя авторские комментарии; после проверки пользователь повторяет сохранение. Потеря ответа не подтверждает откат — сначала проверить архив. Повтор одинакового снимка идемпотентен, в том числе при параллельном сохранении.

Недельная сводка охватывает последнюю завершённую календарную неделю понедельник–воскресенье Europe/Moscow. По решению пользователя 10.11 сервер автоматически сохраняет её в понедельник в 00:00 МСК (проверка каждые 30 секунд). Нужен работающий backend. При запуске после простоя догоняется только последняя завершённая неделя; пропущенные давние недели и их историческое состояние не выдумываются. Если ручной снимок той же недели/режима уже существует, автоматический дубль не создаётся. Отчёт фиксирует данные при фактическом формировании, не гарантирует состояние БД в прошедшую полночь. Ошибка записи откатывается и повторяется, её статус виден в UI. Рассылки нет. Настройка `APP_WEEKLY_ARCHIVE_ENABLED=true` включена по умолчанию; false отключает фоновую запись, ручное сохранение остаётся.

Архив хранит неизменяемые снимки без автоматического удаления, по 20 на странице. Недельные строки выделены бледно-фиолетовым. Нажатие открывает отчёт в окне по центру; длинного документа под архивом больше нет. «Просмотр», «Печать» и «Сохранить PDF» — отдельные действия. PDF скачивается с backend, не открывает печать и не требует сети. Используется уже закреплённый Pillow и локальный Arial/DejaVu/Liberation; при отсутствии шрифта — явный 503 PDF_FONT_UNAVAILABLE. PDF растровый, до 30 страниц, с переносами кириллицы; текстовый поиск/копирование доступны в Markdown и JSON. Превышение лимита даёт 413 без обрезания. Тексты не интерпретируются как HTML. Отправка Telegram/Макс не реализована.

Схема `report-snapshot-v1` и SHA-256 проверяются при чтении, листании архива и идемпотентном повторе. Повреждение даёт 503 REPORT_INTEGRITY_FAILED без сырого содержимого; повреждённая запись не затирается. Дата реализации в UI задаётся по Москве; дополнительные поля решения проверяются повторным чтением истории, включая эквивалентные UTC timestamps. Пробелы вокруг обязательных текстовых полей нормализуются до отправки, чтобы не давать ложное «сохранение не подтверждено» после нормализации сервером.

## SQLite и новые API

SQLite v5 аддитивно добавляет только `report_snapshots`; существующие v1–v4 сначала получают backup через SQLite backup, затем атомарную миграцию. Повтор v5 не создаёт новый backup. Импортный manifest/source hash и модельные schemas/prompts/replay keys не менялись; read-only preview теперь также принимает v5. Передача новой схемы не означает разрешение сбрасывать базу. Во время разработки рабочие базы не мигрировались — только отдельные var-наборы.

| Метод | Адрес | Назначение |
|---|---|---|
| GET | /api/v1/monitoring | view=topics/sources; q/category/priority/status/support/date_from/date_to/offset/limit; один снимок SQLite |
| GET | /api/v1/monitoring/{topic\|source}/{id} | Актуальная версия и revision выбранного объекта |
| POST | /api/v1/reports/archive | ReportDraft → ReportSnapshot; устаревшее содержимое — 409 |
| POST | /api/v1/reports/archive/weekly | Сохранить снимок завершённой недели |
| GET | /api/v1/reports/archive | Архив, offset/limit |
| GET | /api/v1/reports/archive/{report_id} | Неизменяемый сохранённый отчёт |
| GET | /api/v1/reports/archive/{report_id}/pdf | Проверенный снимок → локальный PDF, attachment; 409 занят, 413 размер, 503 шрифт/целостность |
| GET | /api/v1/reports/weekly-schedule | WeeklySchedule: включение, следующая полночь, ошибка и политика catch-up |

Read DTO — `backend/app/workspace_schemas.py`; TypeScript и проверка ответа — `frontend/src/workspace-contracts.ts`/`api.ts`. Формы восьми контрактов — [data/contracts/workspace.json](../data/contracts/workspace.json), это не зарегистрированные данные/действующие replay requests. OpenAPI описывает новые ответы; CLI export-schemas включает 62 схемы. Существующие HTTP сохраняются. Сейчас read-проекция сканирует подготовленный набор в одной транзакции и затем отбирает страницу; это не проверка промышленной производительности.

## Запуск, чтобы посмотреть

Первый терминал, из корня проекта:

```powershell
Set-Location backend
$demoJson = ..\.venv\Scripts\python.exe -X utf8 -m scripts.prepare_acceptance_demo
if ($LASTEXITCODE -ne 0) { throw 'Демо не подготовлено' }
$demo = $demoJson | ConvertFrom-Json
$demo.selected_files
$demo.text_manifest
foreach ($entry in $demo.environment.PSObject.Properties) {
    Set-Item -Path "Env:$($entry.Name)" -Value $entry.Value
}
..\.venv\Scripts\python.exe -X utf8 -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Второй терминал, из корня:

```powershell
Set-Location frontend
npm run dev
```

Если Node не в PATH, вместо последней команды:

```powershell
$taskNodePath = (Get-Content -Encoding UTF8 ..\var\tooling\node\active-path.txt -Raw).Trim()
$env:PATH = "$taskNodePath;$env:PATH"
& "$taskNodePath\npm.cmd" run dev
```

Открыть http://127.0.0.1:5173. Linux/macOS — эквивалентный ../.venv/bin/python, environment из demo-settings.json и npm. Порты должны быть свободны; собственный прежний показ остановить Ctrl+C в его терминалах. Новый запуск подготовки создаёт отдельный var/acceptance-demo-UUID, не меняет .env и рабочую SQLite. Для повторного открытия **того же** архива после закрытия терминала читать сохранённый `$demo.folder/demo-settings.json`, а не готовить новую базу.

```powershell
# Вместо пути указать folder, напечатанный при первоначальной подготовке.
$demo = Get-Content -Raw -Encoding UTF8 C:\путь\к\demo-settings.json | ConvertFrom-Json
foreach ($entry in $demo.environment.PSObject.Properties) {
    Set-Item -Path "Env:$($entry.Name)" -Value $entry.Value
}
```

Маршрут проверки: три темы → «Обращения» (пять источников, включая unclassified/unknown) → карточка контакта/источник (partial 4/5) → импорт/повтор без дублей → обработка (9/9 материалов, 5/5 источников) → сохранение решения → выбор карточек → резюме/архив/скачивание → решение изменилось, а старый отчёт нет → остановка/запуск того же backend → архив сохранился. Искусственное аудио — тишина; authored ответы не являются распознаванием. Даты набора фиксированы 02–06.11.2026; приёмочная неделя 02–08.11.2026. Остановка — Ctrl+C в двух терминалах.
