## Purpose / Big Picture


Проверить общий прототип после подключения интерфейса и дать воспроизводимый запуск без изменения `.env` и рабочих баз. Пользователь увидит возраст обращения от исходной даты создания и сможет отличать частичный анализ, ошибки, неизвестный приоритет и сохранённое решение. Возраст не означает длительность открытого тикета: upstream-статуса закрытия у нас нет.

По `docs/org_feedback.txt`, вопрос 14, обезличенность входных данных является допущением кейса. Полное обезличивание не становится обязательной новой функцией прототипа. Нынешняя synthetic-only политика загрузки/оригиналов остаётся фактическим ограничением проверенной реализации; корпоративная авторизация и разрешение на реальные данные не следуют из допущения кейса.

## Context and Orientation


`backend/app/ingestion/media_normalizer.py` обрабатывает зарегистрированные файлы через ApprovedAsset и строгий replay; `backend/app/public_views.py` ограничивает оригиналы. `backend/scripts/check_partial_weekly_integration.py` запускает обычный backend в отдельном процессе на свободном localhost-порту, прерывает worker и повторяет обработку. `backend/scripts/check_frontend_media_http.py` проверяет React через jsdom против настоящего HTTP/SQLite. Это не визуальная приёмка браузера. `frontend/src/components/SourceViewer.tsx` показывает обращение, его исходную дату и фрагменты; туда добавляется возраст. Все результаты/новые демобазы создаются только в новых каталогах `var/`.

## Plan of Work


Сначала сохранить хеши `.env` и SQLite, уточнить ограничения в актуальных handoff/концепции. Затем отдельным компонентом показывать прошедшее время с `TicketInput.created_at` с обновлением раз в минуту и явным сообщением о будущей дате. API и импорт не меняются; сохранять вычисленный возраст в базе нельзя.

Для У1 дополнить `data/security/` случаями инструкций в ASR/VL-тексте и повреждёнными media payload. В тестах проверять отсутствие сетевых/файловых побочных действий, маскирование до textual request/cache/recording, отклонение чужих evidence и отсутствие регистрации плохих файлов. Искусственные ASR/VL ответы не проверяют устойчивость реальной модели к инструкциям в звуке или пикселях.

Далее выполнить полные тесты и существующие процедуры настоящего HTTP. Текстовый сценарий/replay, media import/recovery, partial retry/restart, решения/ручные исправления и отчёт принимаются по фактическим результатам, а не по описанию плана. Визуальный редизайн, независимый benchmark У2, live endpoints и корпоративная авторизация не входят в эту задачу.

Для стабильного показа создан `backend/scripts/prepare_acceptance_demo.py`: подготовка строит известные authored записи в отдельном training-каталоге, а пользовательская демонстрационная SQLite заполняется импортом и обычным строгим replay. Два источника о сохранении счёта дают одну повторяющуюся тему; экспорт, контакт и неясный review дают разные категории/приоритеты. Из backend запускать `..\.venv\Scripts\python.exe -X utf8 -m scripts.prepare_acceptance_demo`; JSON возвращает только пути новой среды и безопасные параметры запуска. Даты фикстуры 02–06.11.2026 фиксированы: недельные цифры при показе позже могут отличаться.

## Idempotence and Recovery


Не менять рабочие базы, не удалять наборы и не перенастраивать `.env`. Проверки создают отдельные UUID-каталоги. Ошибочный прогон сохраняет свой отчёт и повторяется в новом каталоге. Никакая SQLite-транзакция не объявляется транзакцией с файлами. Обновление часов в браузере не меняет source_version, hash, статус и историю.

## Surprises & Discoveries


Исходное состояние: U4 merge уже в main. У демонстрации один источник, поэтому default фильтр повторяющихся тем её скрывает. Для осмотра выбирать «Все темы». Browser host ранее недоступен; не подменять визуальный прогон jsdom-проверкой.

Итоговая попытка Computer Use снова вернула The browser access host is unavailable; обход не выполнялся. В commit-истории main есть дополнительные frontend review/create тесты, поэтому финальное число UI tests — 332 (включая 3 новых проверки возраста), а не прежние 284. Preview импортера возвращает invalid envelope, commit выбрасывает безопасный RepositoryError; новые тесты сверены с обоими существующими исходами без изменения импортера.
